# Lab 01 预期分析

## 1. 部分寄存器状态

| 指令执行后 | `RAX` |
|---|---|
| `movabsq $0x1122334455667788,%rax` | `0x1122334455667788` |
| `movb $0xff,%al` | `0x11223344556677ff` |
| `movw $0xabcd,%ax` | `0x112233445566abcd` |
| `movl $0x12345678,%eax` | `0x0000000012345678` |

## 2. 为什么最终退出状态是 120

最终退出参数为：

```text
0x0000000012345678
```

shell 通常展示等待状态中的低 8 位退出码：

```text
0x78 = 120
```

因此退出码只能用于证明低 8 位，不能替代 GDB 对完整寄存器的观察。

## 3. `companion.c` 的典型优化结果

`zero_extend_u32` 常见：

```asm
movl %edi, %eax
ret
```

原因是写 `EAX` 自动清零 `RAX` 高 32 位。

`sign_extend_i32` 常见：

```asm
movslq %edi, %rax
ret
```

原因是有符号值必须复制 bit 31 到高 32 位。

不同 GCC 版本可能选择语义等价的编码，应根据指令语义判断，不要依赖字面模板。
