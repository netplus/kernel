# A10 实验：公共子表达式与重复计算消除

## 要验证的问题

同一基本块中，如果两个源码表达式计算完全相同的值，优化后的机器代码是否仍然会把它们各算一次？本实验使用：

```c
long x = (a + b) * c;
long y = (a + b) * c;
return x + y;
```

对比 `-O0`、`-Og` 和 `-O2` 下的实际反汇编。

这里观察的是**最终机器代码没有重复计算相同值**这一事实。不要把某段反汇编机械地归因于 GCC 某一个特定优化 pass；公共子表达式消除、value numbering、表达式规范化和代数化简等优化可能共同影响最终结果。

## 构建与运行

```bash
make clean
make all
make run
make inspect
```

## 本次实际验证环境

```text
GCC 14.2.0
GNU binutils 2.44
x86-64
```

三个二进制均实际运行得到：

```text
repeated_expr=180
```

并以 exit 0 结束。

## `-O0`：重复表达式被分别求值

本次 `-O0` 反汇编中，第一次 `(a + b) * c` 对应一组：

```asm
add    %rax,%rdx
imul   %rdx,%rax
mov    %rax,-0x8(%rbp)
```

随后第二次表达式又重新加载参数，并再次执行：

```asm
add    %rax,%rdx
imul   %rdx,%rax
mov    %rax,-0x10(%rbp)
```

因此这里可以直接从机器代码看到：源码中的两次相同计算仍是两次真实计算，并分别保存到两个栈槽。

## `-Og/-O2`：只计算一次，再复用中间值

本次 GCC 14.2.0 下，`-Og` 和 `-O2` 的 `repeated_expr()` 都化为：

```asm
add    %rsi,%rdi
imul   %rdx,%rdi
lea    (%rdi,%rdi,1),%rax
ret
```

执行过程是：

```text
RDI = a + b
RDI = (a + b) * c
RAX = RDI + RDI
```

因此 `(a + b) * c` 只被真实计算一次。其结果继续保存在 `%rdi` 中，最后通过 `lea` 计算两倍值并写入 ABI 返回寄存器 `%rax`。

这也展示了一个重要事实：优化后的“中间变量”不需要对应源码变量 `x`、`y` 各自独立的栈槽。只要语义允许，编译器可以让一个机器级 value 同时代表两个源码表达式的共同结果。

## `RFLAGS` 观察

关键指令对标志位的影响不同：

- `add %rsi,%rdi` 会更新算术标志位；
- 两操作数 `imul %rdx,%rdi` 会根据乘法结果更新 `CF`/`OF`，其余算术标志位不能作为后续逻辑依据；
- `lea (%rdi,%rdi),%rax` 不修改 `RFLAGS`；
- 本函数后续没有条件跳转，因此这些标志位没有参与控制流。

所以这里的 `lea` 应理解为普通整数地址形式计算，而不是“取地址”语义。

## 观察结论的边界

本实验能证明的是当前编译器、当前源码和当前选项产生了上述机器代码。它不能证明：

- 所有相同源码表达式都能被合并；
- 跨越具有可观察副作用的操作也一定能复用旧值；
- 对 `volatile` 对象的访问可以任意删除或合并；
- GCC 必然由某个固定名称的单一 pass 完成这一变化。

阅读优化汇编时，应以最终数据依赖和机器指令为准，而不是从源码变量数量推断寄存器或栈槽数量。
