# 第 1 课：CPU 执行模型、寄存器宽度与 `mov`

## 1. 本课要解决什么问题

第一次接触汇编时，最容易陷入两个误区：

1. 把汇编当成一张需要背诵的指令表；
2. 试图把每条汇编机械地翻译成一行 C 代码。

更有效的方法，是先建立一个稳定的执行模型。看到任何一条指令时，先问：

```text
数据现在放在哪里？
这条指令读取什么？
这条指令修改什么？
修改了多少位？
下一条指令从哪里执行？
```

本课围绕一个最小模型展开：

```text
CPU 可观察状态 = RIP + 通用寄存器 + RSP + RFLAGS + 内存
```

后续的数组、栈、函数调用、系统调用、中断和上下文切换，都是在这个模型上继续增加规则。

本课实验位于：

```text
assembly/labs/01-register-width/
```

## 2. 分层学习路线

不同基础的读者可以采用不同深度。

### 第一次阅读：先掌握主线

只需要回答：

- `RAX/EAX/AX/AL` 是什么关系；
- 为什么写 `EAX` 会清零 `RAX` 高 32 位；
- `mov` 的源和目标分别是谁；
- 如何用 GDB 验证寄存器变化。

### 第二次阅读：理解设计原因

重点理解：

- x86 为什么保留多种寄存器宽度名称；
- 32 位写入为什么采用零扩展语义；
- 汇编语义与 CPU 微架构为什么要分开看；
- 汇编源文件、目标文件和可执行文件分别是什么。

### 第三次阅读：连接系统知识

继续关注：

- System V AMD64 ABI 如何规定参数和返回值；
- ELF 符号、节和入口点如何配合；
- Linux 系统调用为什么使用 `RAX` 和 `RDI`；
- 内核入口代码为什么必须精确控制寄存器宽度。

## 3. 从一段 C 代码开始

```c
long add(long a, long b)
{
    return a + b;
}
```

在 Linux x86-64 的 System V AMD64 ABI 下，优化后的核心汇编可能是：

```asm
add:
    leaq (%rdi,%rsi), %rax
    ret
```

初学阶段先不深入 `lea` 和 `ret`，只观察 ABI 给出的角色：

```text
RDI = 第一个整数或指针参数 a
RSI = 第二个整数或指针参数 b
RAX = 整数或指针返回值
```

CPU 并不知道变量名 `a`、`b`，也不知道 C 类型名 `long`。它只看到寄存器中的位模式，并按指令规定进行运算。

这带来一个非常重要的认识：

> 高级语言中的变量、类型和表达式，在机器代码中通常会变成寄存器、内存位置、位宽和控制流。

## 4. CPU 的五部分可观察状态

### 4.1 `RIP`：接下来执行哪里

`RIP` 是指令指针。它决定 CPU 下一步从哪个地址取指令。

正常顺序执行时，`RIP` 移动到下一条指令；遇到以下事件时，执行位置可能被改变：

```text
jmp / jcc       跳转
call / ret      函数调用与返回
syscall         进入内核
中断或异常       被硬件转移到处理入口
iretq/sysretq   返回先前执行环境
```

x86 指令长度不固定，一条指令可能占 1～15 字节。因此反汇编中相邻地址不一定固定增加 4。

关联知识：很多 RISC 架构使用固定长度或较规则的指令编码，取指和译码更简单；x86 通过复杂编码换取了长期兼容性和较高代码密度。

### 4.2 通用寄存器：CPU 的直接工作区

x86-64 有 16 个主要通用寄存器：

```text
RAX RBX RCX RDX
RSI RDI RBP RSP
R8  R9  R10 R11
R12 R13 R14 R15
```

寄存器中可以放：

```text
整数
地址
数组下标
函数参数
返回值
位图
临时结果
```

寄存器本身没有 C 类型标签。位模式：

```text
0xffffffffffffffff
```

既可以解释为无符号最大值，也可以解释为有符号 `-1`，还可能是全 1 位图。含义由指令和程序上下文决定。

### 4.3 `RSP`：当前栈顶

`RSP` 是通用寄存器，但 ABI 和多条专用指令把它作为栈顶指针。

常见 Linux x86-64 用户栈向低地址增长：

```text
高地址
+--------------------+
| 较早的数据         |
+--------------------+
| 返回地址           |
+--------------------+
| 保存的寄存器       |
+--------------------+
| 局部变量           |
+--------------------+  ← RSP
低地址
```

本课实验不修改栈，但要开始养成习惯：调试汇编时始终知道 `RSP` 指向哪里。

### 4.4 `RFLAGS`：上一次运算留下的条件状态

`RFLAGS` 中包含多种控制位和状态位。本课先认识：

| 标志 | 直观问题 |
|---|---|
| `ZF` | 结果是否为 0？ |
| `SF` | 结果最高位是否为 1？ |
| `CF` | 无符号运算是否发生进位或借位？ |
| `OF` | 有符号结果是否超出表示范围？ |

`add`、`sub`、`cmp`、`test` 等会更新相关标志；普通 `mov` 和 `lea` 通常不会更新这些算术标志。

第三课会系统分析条件码。本课先记住：

> 数据搬运和算术判断是两个不同维度；不能看到寄存器变化就默认标志位也被重新计算。

### 4.5 内存：大量代码和数据的存储位置

寄存器数量有限，大部分代码和数据位于内存。

下面两条指令看起来只差一对括号，但语义完全不同：

```asm
movq %rbx, %rax
movq (%rbx), %rax
```

第一条复制寄存器中的值：

```text
RAX = RBX
```

第二条把 `RBX` 当作地址，读取该地址处的 8 字节：

```text
RAX = memory64[RBX]
```

地址与解引用将在第二课展开。本课只建立区别。

## 5. 用最小程序观察状态变化

实验核心代码：

```asm
_start:
    movabsq $0x1122334455667788, %rax
    movb    $0xff, %al
    movw    $0xabcd, %ax
    movl    $0x12345678, %eax

    movq    %rax, %rdi
    movq    $60, %rax
    syscall
```

先不考虑退出逻辑，逐条观察 `RAX`。

### 第一步：写入完整 64 位模式

```asm
movabsq $0x1122334455667788, %rax
```

结果：

```text
RAX = 0x1122334455667788
```

### 第二步：只写低 8 位

```asm
movb $0xff, %al
```

结果：

```text
RAX = 0x11223344556677ff
```

只有 bit 7..0 被替换。

### 第三步：只写低 16 位

```asm
movw $0xabcd, %ax
```

结果：

```text
RAX = 0x112233445566abcd
```

只有 bit 15..0 被替换。

### 第四步：写低 32 位

```asm
movl $0x12345678, %eax
```

结果：

```text
RAX = 0x0000000012345678
```

这一步与前两步不同：写 `EAX` 会自动清零 `RAX` 高 32 位。

状态表：

| 执行后 | `RAX` |
|---|---|
| 初始 64 位写入 | `0x1122334455667788` |
| 写 `AL` | `0x11223344556677ff` |
| 写 `AX` | `0x112233445566abcd` |
| 写 `EAX` | `0x0000000012345678` |

这张表是本课最重要的实验结论。

## 6. 一个寄存器为什么有多个名字

以 `RAX` 为例：

```text
RAX   64 位，bit 63..0
EAX   32 位，bit 31..0
AX    16 位，bit 15..0
AL     8 位，bit 7..0
AH     8 位，bit 15..8
```

它们不是五个独立寄存器，而是同一个寄存器的不同访问窗口：

```text
63                              32 31              16 15       8 7        0
+--------------------------------+------------------+-----------+----------+
|                                |                  |    AH     |    AL    |
+--------------------------------+------------------+-----------+----------+
<------------------------------ RAX -------------------------------------->
                                  <--------------- EAX ------------------->
                                                     <-------- AX -------->
```

这种命名来自 x86 的兼容历史：

```text
8086 时代：AX
32 位扩展：EAX
64 位扩展：RAX
```

旧名称被保留下来，使新处理器可以继续支持旧代码和较小宽度的数据运算。

其他常见对应关系：

```text
RBX / EBX / BX / BL / BH
RCX / ECX / CX / CL / CH
RDX / EDX / DX / DL / DH
RSI / ESI / SI / SIL
RDI / EDI / DI / DIL
R8  / R8D / R8W / R8B
```

`AH/BH/CH/DH` 属于历史高 8 位寄存器，在涉及 REX 前缀时存在编码限制。初学阶段知道它们访问 bit 15..8 即可，不建议主动使用。

## 7. 为什么写 `EAX` 会清零高 32 位

这是 x86-64 架构规定，不是编译器偶然产生的效果。

从程序语义看：

```asm
movl value, %eax
```

不仅确定 `EAX`，也完整确定了整个 `RAX`：

```text
RAX = zero_extend_64(EAX)
```

这样设计有几项收益。

### 7.1 自然完成零扩展

C 代码：

```c
uint64_t f(uint32_t x)
{
    return x;
}
```

32 位值写入 `EAX` 后，高位天然为 0，通常不需要额外清零。

### 7.2 消除旧高位依赖

如果写 `EAX` 后高位仍保留，处理器和程序都必须把新低 32 位与旧高 32 位合并。清零规则使结果完全由当前指令决定。

### 7.3 有利于寄存器重命名和依赖分析

现代 CPU 内部会进行寄存器重命名和乱序执行。完整确定结果能够减少不必要的数据依赖。

这里需要区分两层：

```text
架构语义：写 EAX 后 RAX 高位必须为 0
微架构收益：处理器更容易消除旧值依赖
```

前者是程序必须依赖的规则；后者是设计带来的实现优势。

## 8. `mov` 的基本语义

AT&T 语法通常写作：

```text
mov<宽度> 源, 目标
```

常见后缀：

| 后缀 | 位宽 | 汇编传统名称 |
|---|---:|---|
| `b` | 8 位 | byte |
| `w` | 16 位 | word |
| `l` | 32 位 | long |
| `q` | 64 位 | quadword |

注意：汇编中的 `l` 表示 32 位，与 Linux x86-64 C 语言中通常为 64 位的 `long` 不是同一个命名体系。

### 8.1 立即数到寄存器

```asm
movq $100, %rax
```

`$100` 表示数值本身：

```text
RAX = 100
```

### 8.2 寄存器到寄存器

```asm
movq %rbx, %rax
```

```text
RAX = RBX
RBX 不变
```

`mov` 更接近“复制”，不是把源位置清空后移动。

### 8.3 内存与寄存器

```asm
movq (%rbx), %rax
movq %rax, (%rbx)
```

分别表示内存读取和内存写入。详细有效地址计算在第二课展开。

普通 `mov` 通常不能同时让两个显式操作数都是内存：

```asm
movq (%rax), (%rbx)     # 非法的普通 mov 形式
```

通常要通过寄存器中转。

### 8.4 `mov` 不更新算术标志

```asm
cmpq %rsi, %rdi
movq %rax, %rbx
jg target
```

中间的 `mov` 不会覆盖 `cmp` 产生的条件码。

关联知识：

```asm
xorl %eax, %eax
```

也能把 `RAX` 清零，但 `xor` 会更新算术标志；而 `movl $0,%eax` 不会。两种写法的数据结果相同，附带状态不同。

## 9. 零扩展与符号扩展

把较小位宽的数据放入较大寄存器时，必须决定高位如何补充。

### 9.1 零扩展

适用于无符号数：

```text
8 位 0xff → 64 位 0x00000000000000ff
```

常见指令：

```asm
movzbl %dil, %eax
```

先零扩展到 32 位；写 `EAX` 又保证 `RAX` 高 32 位为 0。

### 9.2 符号扩展

适用于补码有符号数：

```text
8 位 0xff（-1）→ 64 位 0xffffffffffffffff
```

常见指令：

```asm
movsbq %dil, %rax
movslq %edi, %rax
```

符号扩展复制原值最高位到新增高位。

### 9.3 为什么不能混用

同一个位模式 `0xffffffff`：

```text
按 uint32_t 解释：4294967295
按 int32_t 解释：-1
```

扩展到 64 位时：

```text
零扩展：0x00000000ffffffff
符号扩展：0xffffffffffffffff
```

所以在反汇编中，`movz*` 与 `movs*` 经常暴露源代码中的 signed/unsigned 语义。

## 10. AT&T 与 Intel 语法对照

| 特征 | AT&T | Intel |
|---|---|---|
| 操作数顺序 | 源, 目标 | 目标, 源 |
| 寄存器 | `%rax` | `rax` |
| 立即数 | `$10` | `10` |
| 宽度 | `movq` 后缀 | 由寄存器或 `QWORD PTR` 表示 |

示例：

```asm
# AT&T
movq %rbx, %rax
movq 8(%rbx), %rax

# Intel
mov rax, rbx
mov rax, QWORD PTR [rbx + 8]
```

学习时建议：

- 熟练阅读 AT&T，因为 GCC 输出、GNU `as` 和大量内核代码会使用它；
- 能够阅读 Intel，因为处理器手册、调试器和逆向工具常使用它；
- 不要在同一段分析中不加说明地混用两种操作数顺序。

## 11. 汇编文件中哪些内容会由 CPU 执行

```asm
    .section .text
    .global _start
    .type _start, @function

_start:
    movq $60, %rax
    xorl %edi, %edi
    syscall
```

这里包含三类内容。

### 11.1 汇编伪指令

```asm
.section .text
.global _start
.type _start, @function
```

它们由汇编器处理，用于组织目标文件，不是 CPU 指令。

### 11.2 标签和符号

```asm
_start:
```

标签把名称绑定到当前位置，方便链接器、加载器、调试器和反汇编器定位。

### 11.3 机器指令

```asm
movq
xorl
syscall
```

这些会被编码成机器字节，由 CPU 执行。

关联知识：伪指令和符号最终会参与 ELF 节、符号表和重定位的生成，后续 ELF 课程会继续展开。

## 12. 从源文件到运行程序

构建流程：

```text
register_width.s
        ↓ as
register_width.o
        ↓ ld
register_width（ELF 可执行文件）
        ↓ Linux loader
虚拟地址空间中的代码和数据
        ↓ CPU
机器指令执行
```

常用命令：

```bash
as --64 -g -o register_width.o register_width.s
ld -o register_width register_width.o
objdump -drS register_width
objdump -drS -Mintel register_width
readelf -h -S -s register_width
```

不同工具回答不同问题：

```text
objdump   机器代码是什么？
readelf   ELF 如何组织？有哪些节和符号？
nm        符号地址是什么？
gdb       运行时状态如何变化？
```

## 13. 为什么程序从 `_start` 而不是 `main` 开始

本实验使用：

```bash
ld -o register_width register_width.o
```

没有链接 C 运行库，因此入口直接是 `_start`。

常规 C 程序中，执行路径大致是：

```text
Linux 装载 ELF
    ↓
进入运行库入口 _start
    ↓
初始化进程运行环境
    ↓
调用 main
    ↓
处理返回值并调用 exit
```

所以 `main` 是 C 运行环境定义的程序入口，不是 CPU 或 Linux ELF 机制唯一认可的入口名称。

## 14. 实验中的系统调用只需要先理解两点

```asm
movq %rax, %rdi
movq $60, %rax
syscall
```

Linux x86-64 原始系统调用约定中：

```text
RAX = 系统调用号
RDI = 第一个参数
```

系统调用号 60 是 `exit`，所以这段代码执行：

```text
exit(原 RAX 的低位值)
```

Shell 通常只能观察退出状态的低 8 位，所以：

```text
0x12345678 → 0x78 → 120
```

这说明：

> Shell 退出状态不是查看完整 64 位寄存器的工具；完整值应使用 GDB 观察。

系统调用 ABI 和内核入口将在后续单独分析。

## 15. 用 GDB 建立“执行前—执行后”习惯

进入实验目录：

```bash
make clean all
make gdb
```

手工调试时常用：

```gdb
break _start
run
x/i $rip
info registers rax rip rsp eflags
si
```

每执行一条指令，记录：

| 项目 | 问题 |
|---|---|
| 当前指令 | `RIP` 指向什么？ |
| 输入 | 读取了哪个立即数、寄存器或内存？ |
| 输出 | 写了哪个寄存器或内存？ |
| 位宽 | 写了 8、16、32 还是 64 位？ |
| 附带状态 | 是否修改了 `RFLAGS`？ |
| 下一步 | `RIP` 如何变化？ |

这套记录方法比只盯着最终结果更重要，因为后续分析长函数时必须依靠逐步状态推导。

## 16. 常见误区

### 误区 1：`RAX`、`EAX`、`AX` 是独立寄存器

错误。它们是同一个寄存器的不同访问宽度。

### 误区 2：所有部分写入都会保留高位

错误。写 `AL/AX` 保留未覆盖部分，写 `EAX` 会清零高 32 位。

### 误区 3：`mov` 会把源清空

错误。`mov` 复制数据，源通常保持不变。

### 误区 4：寄存器中的值天然有类型

错误。CPU 看到位模式，signed/unsigned、整数/地址由指令和上下文决定。

### 误区 5：每一行汇编源文件都是 CPU 指令

错误。标签和伪指令服务于汇编、链接和调试。

### 误区 6：程序退出码可以显示完整寄存器值

错误。退出状态通常只保留低 8 位。

### 误区 7：架构执行模型就是现代 CPU 的内部流水线

错误。本课模型描述架构可观察结果；现代 CPU 内部可能乱序执行、拆分微操作并使用寄存器重命名，但最终必须表现得符合架构语义。

## 19. 完成标准

完成本课后，应能不依赖猜测地解释：

```asm
movabsq $0x1122334455667788, %rax
movb    $0xff, %al
movw    $0xabcd, %ax
movl    $0x12345678, %eax
```

并准确回答：

```text
每条指令写了哪几位？
哪些旧位被保留？
为什么写 EAX 会影响完整 RAX？
RFLAGS 是否被修改？
如何用 GDB 验证？
```

如果这些问题能够稳定回答，就具备进入地址计算、解引用和复杂寻址课程的基础。
