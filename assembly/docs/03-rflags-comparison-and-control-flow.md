# 第 3 课：`RFLAGS`、比较、条件跳转与基本块

## 1. 本课要解决什么问题

高级语言中，我们可以直接写：

```c
if (a > b)
    return a;
```

CPU 需要把这句话拆成两个问题：

```text
问题 1：如何得到“a 与 b 的关系”？
问题 2：如何根据这个关系选择下一条执行路径？
```

x86 的基本设计是：

```text
算术或逻辑指令产生结果性质
        ↓
把这些性质记录到 RFLAGS
        ↓
条件跳转、条件置位或条件移动读取 RFLAGS
```

典型序列：

```asm
cmpq %rsi, %rdi
jg greater
```

`cmp` 不保存减法结果，而是记录：

```text
结果是否为 0？
结果最高位是否为 1？
是否发生无符号进位或借位？
是否发生有符号溢出？
```

`jg` 再根据这些标志判断是否跳转。

本课实验位于：

```text
assembly/labs/03-flags-and-branches/
```

## 2. 分层学习路线

### 第一次阅读：掌握主线

先记住：

- `cmp source,destination` 概念上计算 `destination-source`；
- `test reg,reg` 常用于判断 0 和符号；
- `je/jne` 只看是否相等，与 signed/unsigned 无关；
- `jg/jl` 用于有符号比较；
- `ja/jb` 用于无符号比较；
- 条件跳转会把代码分成多个基本块。

### 第二次阅读：理解标志公式

重点理解：

- `CF` 与 `OF` 是两个不同问题；
- 为什么有符号 `<` 需要判断 `SF != OF`；
- `setcc` 和 `cmovcc` 如何复用相同条件码；
- 为什么两条相关指令之间不能随意插入会改标志的指令。

### 第三次阅读：连接编译器与内核

继续分析：

- `if/else`、循环和边界检查如何形成控制流图；
- 分支预测与 `cmov` 的性能取舍；
- 内核如何用 `test` 检查状态位；
- 系统调用和异常返回路径如何根据标志与状态选择分支。

## 3. 先把 `RFLAGS` 看成“结果说明书”

假设执行：

```asm
subq %rsi, %rdi
```

除了得到新的 `RDI`，CPU 还会记录这次结果的若干性质。

初学阶段可以把关键标志理解为四个问题：

| 标志 | 它回答的问题 |
|---|---|
| `ZF` | 结果是否等于 0？ |
| `SF` | 结果的最高位是否为 1？ |
| `CF` | 按无符号运算理解，是否发生进位或借位？ |
| `OF` | 按有符号运算理解，数学结果是否超出表示范围？ |

还有一些暂时不作为主线的标志：

| 标志 | 用途概览 |
|---|---|
| `PF` | 结果最低字节的奇偶校验性质 |
| `AF` | 低 4 位进位，主要是历史 BCD 语义 |
| `DF` | 字符串指令地址递增还是递减 |
| `IF` | 是否允许可屏蔽中断 |

关键提醒：

> 标志位描述的是某次具体运算的结果性质，不是寄存器永久附带的属性。

只要后续执行了会更新标志的指令，原来的比较信息就可能丢失。

## 4. 哪些指令会修改标志

### 4.1 常见会更新算术标志的指令

```asm
add sub cmp
and or xor test
shl shr sar
inc dec
```

### 4.2 通常不更新算术标志的指令

```asm
mov
lea
push
pop
```

比较以下两段代码。

```asm
cmpq %rsi, %rdi
movq %rax, %rbx
jg greater
```

`mov` 不破坏 `cmp` 的结果，因此 `jg` 仍判断 `RDI-RSI`。

```asm
cmpq %rsi, %rdi
addq $1, %rax
jg greater
```

`add` 会重新写标志，因此 `jg` 判断的是 `RAX+1` 的结果性质，不再是原比较结果。

### 4.3 `inc/dec` 的特殊性

`inc` 和 `dec` 会更新多个标志，但不修改 `CF`。

这是历史兼容语义。它意味着：如果代码正在维护多字长无符号进位链，就不能简单把：

```asm
addq $1, %rax
```

替换为：

```asm
incq %rax
```

数据结果可能相同，但附带的 `CF` 语义不同。

## 5. `cmp`：做减法，但不保存差值

AT&T 语法：

```asm
cmpq source, destination
```

概念操作：

```text
destination - source
```

差值不写回，只更新标志。

例如：

```asm
cmpq %rsi, %rdi
```

概念上计算：

```text
RDI - RSI
```

不是 `RSI-RDI`。

### 5.1 从最简单的相等判断开始

假设：

```text
RDI = 7
RSI = 7
```

执行：

```asm
cmpq %rsi, %rdi
```

概念结果为 0，所以：

```text
ZF = 1
```

随后：

```asm
je equal
```

条件成立。

`je` 和 `jz` 使用同一个条件：

```text
je：从“相等”语义命名
jz：从“结果为零”语义命名
```

机器编码相同。

### 5.2 用操作数顺序还原 C 条件

C 条件：

```c
if (a < b)
```

若 ABI 使：

```text
RDI = a
RSI = b
```

常见写法：

```asm
cmpq %rsi, %rdi
jl a_less
```

因为 `cmp` 计算 `a-b`，`jl` 判断有符号 `a<b`。

如果写成：

```asm
cmpq %rdi, %rsi
```

就变成比较 `b-a`，后续条件也必须反转。

分析未知汇编时，建议先机械写下：

```text
destination - source
```

再判断跳转语义，避免凭直觉把操作数顺序看反。

## 6. `test`：做按位与，但不保存结果

```asm
testq source, destination
```

概念上计算：

```text
destination & source
```

结果不写回，只更新标志；`CF` 和 `OF` 会被清零。

### 6.1 判断是否为零

```asm
testq %rax, %rax
je zero
```

因为：

```text
RAX & RAX = RAX
```

只有 `RAX=0` 时 `ZF=1`。

这比“真的做一次比较”更直接地表达零值测试，也是编译器常见输出。

### 6.2 判断符号

```asm
testq %rax, %rax
js negative
```

按位与结果与原值相同，因此 `SF` 反映原值最高位。

### 6.3 检查位掩码

```asm
testq $0x8, %rax
jnz bit3_set
```

检查：

```text
RAX & 0x8
```

是否非零。

关联知识：Linux 内核大量状态使用位图或 flag 字段表示，例如设备状态、socket 状态和协议标志。汇编中常出现 `test` 加条件跳转的形式。

## 7. `CF` 与 `OF`：不要把两个“溢出”混为一谈

CPU 执行同一组加法位运算，但程序可以把结果解释为无符号数或有符号数。

### 7.1 `CF`：无符号范围问题

使用 8 位示例：

```text
0xff + 1 = 0x00
```

无符号数学结果为 256，8 位放不下，所以：

```text
CF = 1
ZF = 1
OF = 0
```

### 7.2 `OF`：有符号范围问题

8 位补码范围：

```text
-128 ～ 127
```

```text
127 + 1 = 0x80
```

`0x80` 按有符号解释为 `-128`。两个正数相加得到负数，说明有符号数学结果不可表示：

```text
OF = 1
CF = 0
SF = 1
```

### 7.3 对照表

| 运算 | 位模式结果 | `CF` | `OF` | 含义 |
|---|---:|---:|---:|---|
| `0xffff...ffff + 1` | `0` | 1 | 0 | 无符号回绕 |
| `0x7fff...ffff + 1` | `0x8000...0000` | 0 | 1 | 有符号正溢出 |
| `1 + 1` | `2` | 0 | 0 | 两种解释都可表示 |

因此：

```text
判断无符号范围：关注 CF
判断有符号范围：关注 OF
```

## 8. 为什么有符号比较不能只看 `SF`

很多初学者会认为：

```text
结果最高位为 1 → 结果为负 → 左边小于右边
```

这在没有发生有符号溢出时通常成立，但溢出时会失败。

例如 8 位：

```text
127 - (-1) = 128
```

真实数学结果为正，但 8 位结果是：

```text
0x80
```

最高位为 1，即 `SF=1`；同时发生有符号溢出，即 `OF=1`。

真实的有符号“小于”条件使用：

```text
SF != OF
```

在这里：

```text
SF = OF = 1
```

所以“小于”条件不成立，得到正确结论。

可以把 `OF` 看成对 `SF` 的校正信息。

## 9. 有符号与无符号条件码

执行一次：

```asm
cmpq %rsi, %rdi
```

可以从不同类型语义解释同一组标志。

### 9.1 相等比较与符号无关

| 条件 | 指令 | 公式 |
|---|---|---|
| 相等 | `je` / `jz` | `ZF=1` |
| 不等 | `jne` / `jnz` | `ZF=0` |

两个位模式是否相同，不涉及 signed/unsigned。

### 9.2 无符号比较

| C 关系 | 跳转 | 标志公式 |
|---|---|---|
| `<` | `jb` | `CF=1` |
| `<=` | `jbe` | `CF=1 或 ZF=1` |
| `>` | `ja` | `CF=0 且 ZF=0` |
| `>=` | `jae` | `CF=0` |

助记词：

```text
above / below → 无符号
```

### 9.3 有符号比较

| C 关系 | 跳转 | 标志公式 |
|---|---|---|
| `<` | `jl` | `SF != OF` |
| `<=` | `jle` | `ZF=1 或 SF != OF` |
| `>` | `jg` | `ZF=0 且 SF=OF` |
| `>=` | `jge` | `SF=OF` |

助记词：

```text
greater / less → 有符号
```

### 9.4 同一位模式的双重解释

```asm
movq $-1, %rax
cmpq $1, %rax
```

`RAX` 的位模式是全 1。

按有符号解释：

```text
-1 < 1
```

所以 `jl` 成立。

按无符号解释：

```text
ULONG_MAX > 1
```

所以 `ja` 也成立。

这并不矛盾。CPU 保留的是位模式和标志，具体类型语义由后续条件指令决定。

## 10. 同一条件码的三种使用方式

条件码不仅用于跳转。

### 10.1 `jcc`：改变控制流

```asm
cmpq %rsi, %rdi
jge greater_or_equal
```

条件成立时修改 `RIP`。

### 10.2 `setcc`：生成 0 或 1

```asm
cmpq %rsi, %rdi
setl %al
```

结果：

```text
AL = 0 或 1
```

`setcc` 只写一个字节。若要返回规范的 32 位 `int`，常见形式是：

```asm
xorl %eax, %eax
cmpq %rsi, %rdi
setl %al
```

先清零完整 `EAX`，再写低 8 位。

### 10.3 `cmovcc`：不跳转地选择值

```asm
movq %rsi, %rax
cmpq %rsi, %rdi
cmovg %rdi, %rax
```

概念上：

```c
return rdi > rsi ? rdi : rsi;
```

条件成立时复制，不成立时目标寄存器保持原值。

## 11. 条件跳转如何形成基本块

基本块可以理解为一段“从入口开始顺序执行到末尾”的指令序列。

通常满足：

1. 只能从第一条指令进入；
2. 块内中间没有控制转移；
3. 最后一条决定接下来可能去哪。

示例：

```asm
    testq %rdi, %rdi
    jns nonnegative

negative:
    movl $-1, %eax
    ret

nonnegative:
    movl $1, %eax
    ret
```

可以画成：

```text
Block A: test + jns
   ├── 不跳转 → Block B: return -1
   └── 跳转   → Block C: return 1
```

块之间的有向连接构成控制流图 CFG。

阅读复杂汇编时，不要只从上到下连续阅读。更可靠的方法是：

```text
先标出所有跳转目标
再划分基本块
再画出块之间的边
最后恢复 if/else、循环和错误路径
```

## 12. 从 `if/else` 到汇编

C 代码：

```c
long max_signed(long a, long b)
{
    if (a > b)
        return a;
    return b;
}
```

### 12.1 分支版本

```asm
cmpq %rsi, %rdi
jle return_b
movq %rdi, %rax
ret

return_b:
movq %rsi, %rax
ret
```

### 12.2 条件移动版本

```asm
movq %rsi, %rax
cmpq %rsi, %rdi
cmovg %rdi, %rax
ret
```

两者高级语义相同，但机器执行结构不同：

```text
分支版本：RIP 可能走不同路径
cmov 版本：RIP 顺序执行，数据选择发生在寄存器
```

## 13. 循环是带“回边”的控制流

```asm
loop:
    testq %rdi, %rdi
    je done
    subq $1, %rdi
    jmp loop

done:
```

`jmp loop` 从较后位置跳回前面的基本块，形成回边。

识别循环时通常寻找：

```text
初始化块
条件判断块
循环体
更新变量
回跳边
退出块
```

编译器优化后，这些部分可能重排，但回边和退出条件仍是恢复循环结构的重要线索。

## 14. 分支预测与 `cmov` 的设计取舍

现代 CPU 会预测条件跳转结果和目标，以便提前取指和执行。

### 预测正确

控制流几乎无停顿，分支成本可能很低。

### 预测错误

CPU 需要丢弃错误路径上的推测执行结果，并重新从正确路径取指。

因此编译器有时会把很短的分支改成 `cmov`，避免预测失败。但不能简单得出“`cmov` 总是更快”：

- 两边候选值可能都需要提前计算；
- 长路径不适合无条件计算；
- 某些内存访问可能昂贵或可能产生异常；
- 高度可预测的分支本来就很便宜；
- 具体收益依赖微架构和数据分布。

语义分析时先判断代码做什么；性能分析时再研究分支可预测性和指令依赖。

## 15. 常见编译器输出模式

### 15.1 判断是否为 0

C：

```c
return value == 0;
```

可能生成：

```asm
testq %rdi, %rdi
sete %al
```

### 15.2 有符号小于

C：

```c
return left < right;
```

可能生成：

```asm
cmpq %rsi, %rdi
setl %al
```

### 15.3 无符号大于

C：

```c
return left > right;
```

可能生成：

```asm
cmpq %rdi, %rsi
setb %al
```

操作数顺序可能因编译器选择改变，所以必须结合 `cmp` 方向分析，不能只看到 `setb` 就孤立下结论。

### 15.4 检测无符号加法进位

C：

```c
sum = left + right;
carry = sum < left;
```

可能使用：

```asm
addq
setc
```

因为无符号回绕由 `CF` 描述。

## 16. Linux 内核中的关联知识

### 16.1 状态位检查

内核结构体和全局状态常用位图表示。汇编中可能看到：

```asm
testl $MASK, offset(%reg)
jnz state_enabled
```

需要还原为“读取字段、与掩码相与、根据是否非零分支”。

### 16.2 边界检查

数组长度、数据包长度和用户输入长度常按无符号类型处理，因此编译器可能使用：

```text
ja / jae / jb / jbe
```

看到无符号跳转时，应考虑源类型是否为 `size_t`、长度、地址或位图。

### 16.3 错误路径和快速路径

内核函数常有：

```text
正常快速路径
参数错误路径
资源不足路径
异常清理路径
```

条件跳转把这些路径组织成 CFG。阅读时先识别哪条是主路径，哪条是错误分支。

### 16.4 `likely()` / `unlikely()`

这些宏主要影响编译器的代码布局和分支概率判断，不改变 C 语言条件本身。最终汇编仍是普通比较和条件跳转。

### 16.5 系统调用与异常返回

Linux x86-64 入口和返回汇编会根据线程状态、工作标志、用户地址合法性等条件选择不同路径。理解 `test/cmp/jcc` 和基本块，是阅读 `entry_64.S` 的必要基础。

## 17. 分析条件汇编的固定流程

遇到：

```asm
cmpq %rsi, %rdi
jbe target
```

按以下步骤分析。

### 第一步：写出概念运算

```text
RDI - RSI
```

### 第二步：识别条件族

```text
jbe = unsigned <=
```

### 第三步：恢复高级关系

```text
RDI <= RSI，按无符号解释
```

### 第四步：确认寄存器角色

通过 ABI、前序指令或数据流确定 `RDI/RSI` 分别是什么。

### 第五步：划分基本块

确定跳转成立与不成立分别进入哪条路径。

### 第六步：检查标志是否被覆盖

确认 `cmp` 与 `jbe` 之间没有修改标志的指令。

这种机械流程比直接凭助记词猜 C 语义更可靠。

## 18. 常见误区

### 误区 1：`cmp a,b` 计算 `a-b`

在 AT&T 语法中错误。它计算 `b-a`。

### 误区 2：`SF=1` 就一定表示有符号小于

错误。有符号比较还需要结合 `OF`。

### 误区 3：`CF` 和 `OF` 都表示同一种溢出

错误。一个服务无符号语义，一个服务有符号语义。

### 误区 4：`jg` 和 `ja` 可以互换

错误。`jg` 是有符号大于，`ja` 是无符号大于。

### 误区 5：`test` 会把按位与结果写回寄存器

错误。它只更新标志。

### 误区 6：两条相关条件指令之间可以插入任意运算

错误。中间指令若更新标志，后续条件会读取新标志。

### 误区 7：条件移动一定优于分支

错误。它只是另一种实现选择，性能取决于具体上下文。

### 误区 8：反汇编应始终按文本顺序阅读

错误。条件跳转形成 CFG，需要按基本块和边分析。

2. 标出正常路径、条件成立路径和汇合块；
3. 在内核反汇编中寻找 `test mask,field` 形式；
4. 判断长度比较使用的是有符号还是无符号跳转。

## 20. 完成标准

完成本课后，应能准确解释：

```asm
cmpq %rsi, %rdi
jle target
```

并回答：

```text
cmp 概念上计算什么？
jle 属于哪种类型语义？
它依赖哪些标志？
跳转和不跳转分别进入哪个基本块？
中间是否有指令覆盖标志？
```

还应能解释为什么：

```text
-1 < 1（有符号）
ULONG_MAX > 1（无符号）
```

可以由同一位模式和同一次比较同时支持。

如果这些问题能够稳定回答，就具备进入栈、函数调用和更复杂控制流课程的基础。
